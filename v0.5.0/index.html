Portcullis

A daemon for the Docker host that limits what containers can connect to. You put the policy in labels next to the service; Portcullis turns it into nftables rules and keeps them current as containers come and go.

Enforced networks deny everything by default. Each container gets back the destinations its labels list, and every decision is reported with the container, the destination and its domain.

Linux, Docker bridge networks, IPv4. MIT or Apache-2.0. Written in Rust.

  4. DENIEDiccbilling →redis (172.18.0.6)tcp/6379
  5. DENIEDegressbilling →172.18.0.1tcp/22

What a policy covers

Outbound connections
Destinations by address, range, public internet, or hostname and pattern, per protocol and port.
Containers on the same network
Allow all, deny all, or only named containers and multicast groups.
DNS
Which resolvers a container may use, and which names it may look up, so lookups can’t carry data out.
Spoofing and floods
Frames must come from the container’s own bridge port, address and MAC. Misbehaving containers are cut off.
Monitor mode
Report what a policy would deny before enforcing it, and turn the reports into labels.
Boot and failure
Rules are back in place before Docker starts, and stay in place while Portcullis restarts.
